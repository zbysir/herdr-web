# 手机和平板上的那一套

浏览器给的那点触屏支持不够跑一个 TUI：xterm.js 只把 `wheel` 翻译成鼠标上报、完全不管 touch，
点一下就把系统键盘顶出来，而 herdr 这种「占着备用屏幕 + 开了鼠标上报」的程序在手机上两头都不
响应。所以从手势、键盘、底部面板到顶栏和那几块浮层，全是自己接的 —— 这份文档记的是**每一条
为什么长这样**，各自是拿什么 bug 换来的。

[README](../../README.zh-CN.md) 里只说「怎么用」（手势表、软键条怎么配、面板怎么拖）；改这一层的
代码之前读这儿。方法上还有两条硬规矩在 [CLAUDE.md](../../CLAUDE.md) 的触屏那一条里 —— 那是关于
「怎么验」的，比这里任何一条都更容易踩。

## 触屏手势

xterm.js 的触屏支持基本只有「点一下聚焦隐藏 textarea」，剩下全靠自己补。有程序在收鼠标上报时（herdr 这种），触屏手势整个由本项目接管：

手势表（哪个手势干什么）在 [README](../../README.zh-CN.md#手机和平板)，这儿只记**为什么这么分**。

抓取**只认长按**。曾经试过「手指落在框线附近就立刻抓」，翻车了：agent 自己画的框（Claude Code 每个 pane 一个圆角框）竖边同样贯穿整屏，从字符层面和 herdr 的 pane 边框分不出来，于是在框边上一划就变成往 agent 里拖鼠标 —— 手指想滚屏，屏幕上却在选文字。**滑动永远是滑动**，换挡要先按住。

按住之后按**像素吸附**到附近的贯穿线（`SNAP_PX = 24`，约一根手指的落点误差），不是按格数。这条也是踩出来的：原来只允许差一格，而平板上 211 列宽的屏幕一格才 ~6px，手指偏十几个 px 就把 press 落进 pane 里，agent 收到一次拖动、屏幕上什么也没发生 —— 表现就是「手机上根本拖不动 pane」。

只认**贯穿的长线**（框线字符占了这一列 / 这一行 70% 以上、至少 6 格），agent 画的短横线（消息分隔、「2 new messages」那种）都挡在外面。挡不住的是 agent 的外框竖边，但既然只是「按下点挪最多 24px」，猜错了也就是这一次拖动落在框边上。代价：2×2 布局里那条横向分界只占半屏宽，吸不到，得按准一点。

长按期间允许手指飘 16px（`HOLD_SLOP`）。原来是 8px，太苛刻 —— 按住不动的手指本来就会飘十几个 px，一飘长按就被撤销，表现是「长按没反应」。没开鼠标上报的普通 shell 下不抓取（那儿拖一下没有意义），长按仍然是「什么都不做」。

端到端验过：在一个独立的 herdr session 里竖分屏，长按分界线**右边 3 格**再拖，分界从第 45/46 列移到 40/41 列；正好在贯穿竖线上竖划，发出去的仍然只有滚轮上报。

### 第一下只收键盘

键盘弹着的时候点浮层里任何一个按钮（最容易撞上的是各个面板的关闭 ✕），那一下只把键盘收掉、按钮
没反应，再点一次才动。原因和[HERDR-API.md 的「点一行要『一下就跳』」](HERDR-API.md#点一行要一下就跳)是同一个：这一下先把
焦点带走 → 键盘收起 → visualViewport 一变，`--vvh` 和顶栏一起重排 → 手指底下那个元素已经不在原位，
浏览器于是把 click 派给了别人、或者干脆不派。**touch 事件照常来，丢的只有 click。**

所以有一道全局兜底（`web/src/lib/tap.ts`，`main.tsx` 里装一次）：pointerdown / pointerup 落在同一个
可点控件上、手指基本没动，而 250ms 内没等到 click —— 就自己补一次 `el.click()`。几条边界都是刻意的：

- **鼠标不管**（桌面上 click 从不丢，补了就是重复）；手指走过 10px、或者收到 `pointercancel`（开始滚了）
  都不算点。
- **元素已经不在文档里就不补** —— 那说明这一下其实生效了。
- **同一个手势里迟到的那个 click 要吃掉**，不然「关闭」会关两次，第二次落到底下的终端上，等于往 herdr
  里点了一下。判据是「手势序号」而不是时间窗：用户自己连点第二下有它自己的 pointerdown，不会被误吞。
- 自己补的那一下靠一个标志认，**不靠 `isTrusted`** —— 合成事件的 isTrusted 也是 false，拿它当判据会把
  别处派出来的合成 click 当成自己的（测试里踩到过）。

为什么放在 document 上而不是每个按钮自己接：这个毛病跟按钮是谁无关，凡是「浮层里的控件 + 键盘正弹着」
就会中，一个个接总会漏掉下一个新面板。

反过来那一半也修了：**收着的键盘不会被「换个 pane」「点一下字号」顶出来**。这一条踩了两层：

1. 判据错了。原来是「不是手机（宽度 < 440px）就顺手把焦点还给终端」，而平板和横屏的手机都比 440 宽 ——
   在那些机器上 focus 终端就等于把输入法弹出来。现在只有两种情况才聚焦：**键盘本来就开着**（那就把焦点
   还回去），或者**这机器有实体指针**（聚焦不会弹出任何东西）。见 `web/src/App.tsx` 的 `refocusTerm`。
2. 还有一条**点穿**：面板是在 `pointerup` 上关掉的，紧接着浏览器会把那一下的**兼容鼠标事件补发到
   刚露出来的终端上**。两个后果，第二个更隐蔽：

   - xterm 的 mousedown 处理顺手 focus 隐藏输入框 —— 键盘照样冒出来，而那一下压根不是用户在点终端。
   - **herdr 常驻开着鼠标上报**（1002/1003/1006），xterm 会把这些鼠标事件当成真点击报上去 —— 那一下
     幻影点击落在哪个 pane 上，herdr 的焦点就跳到哪儿。表现就是用户报的「弹窗说切换成功，其实面板还在
     老的那边」：跳过去的 socket 调用和幻影点击在抢，点击后到就把焦点又拽回了手指底下那个 pane
     （所以是「有时候」）。

   挡法是一次性闸门（`web/src/term/touch.ts`）：手指在终端外面抬起就打开闸门，接下来第一串鼠标事件
   （mousemove / mousedown / mouseup / click）用掉它 —— 落在终端上就整串挡掉，落在别处就白用掉。
   **判据不能是时间窗**：主线程忙起来那几个事件会被推后到一秒开外（实测「关面板 + herdr 重绘」那一下，
   60ms 的等待量出来是 1008ms），按 700ms 的窗判必然漏。

   **开闸只能认 `pointerup`，不能认 `touchend`** —— 这一条是这个 bug 修了三轮都没修掉的真正原因：
   浮层是在 `pointerup` 的处理里被卸掉的（React 对离散事件同步 flush），而 touch 事件的 target 在
   touchstart 那一刻就钉死了，规范明说「target 被移出文档之后事件仍然派给它，于是不再冒泡到
   document」。所以那一下的 `touchend` **结构性地到不了 document**，闸门永远开不了，前几版等于没装。
   `pointerup` 的传播路径在派发开始时就算好了（那时浮层还在），处理器里把浮层卸掉也不影响它走完；
   触摸的 pointer 事件还有隐式捕获，target 恒等于 `pointerdown` 的 target，判断一字不差。

   还有一条要记住：**xterm 在 `.terminal` 上挂的 mousedown 是无条件 `preventDefault()` + `focus()`**
   （`@xterm/xterm` 的 `CoreBrowserTerminal`），所以「在外面 preventDefault 拦住聚焦」这条路走不通 ——
   只能不让那个事件到它手上，也就是在 document 的捕获段 `stopPropagation`。

   闸门之外还加了一条**不依赖状态**的判据（Chrome / Safari 有这个字段）：终端里出现
   `sourceCapabilities.firesTouchEvents` 为真的鼠标事件，本身就等于点穿 —— 落在终端上的真触摸在
   `touchstart` 那一下就被 `preventDefault` 了，浏览器根本不会为它补发兼容鼠标事件。

   这条洞的后果不止「键盘弹出来」：那一下幻影点击的落点是重新命中测试的，实测能正好落在 **herdr
   移动端顶栏那个 `switch`** 上 —— 于是 herdr 自己的切换面板整屏打开、盖住你刚跳过去的 pane（看着
   就像「没跳过去」），而它那一列条目里 `detach` 就在网页列表行的正下方，再点一下就断开了。

顺带把弹窗改老实了两处：

- `pane.zoom` 回的是 herdr **自己认的** `focused_pane_id`，和请求的 pane 不一样就直说「没跳到 X：
  herdr 说焦点在 Y」，不再一律报「已跳到」。以前那种「屏幕上还在老 pane、弹窗却说成功」最难查 ——
  人会以为是画面没刷新，而实际上焦点真的没动。
- **终端这条连接断着 / 正在重连时也会照样跳成功**（跳转走的是 HTTP，和 PTY 那条 WebSocket 无关），
  但画面是冻住的旧帧 —— 那时候弹窗会多说一句「终端这会儿没连上，画面是旧的」。不说的话表现就是
  「点了没反应，多点几次也一样」。

### 点 herdr 的 switch，开的是我们这张（默认开）

herdr 自己有一套移动端布局：终端窄到一定程度（它的 `ui.mobile_width_threshold`，默认 64 列）
就收成单列，顶上两行状态栏，**右上角贴着屏幕右缘**挂一个 `switch` 按钮 —— 点开是 herdr 自己那张
切换面板（spaces / tabs / menu 一条竖列，一层层点进去）。默认情况下触屏上点它**不再发给 herdr**，
改开[面板一览](../../README.zh-CN.md#面板一览--提示)：按状态排序、能筛、点一行直接跨 workspace 跳过去
并铺满。不想要就在设置 →「终端」里关掉，那时候点它还是 herdr 自己那张。

认按钮的办法是**从那个词顺着背景色把色块摊开**（`web/src/term/mobilebar.ts`），不写死坐标 ——
50 列时色块是 41–50 列 × 1–2 行，64 列时是 55–64 列，宽度跟着布局走。三条都是实测出来的：

- **热区必须是整块，不能只认那六个字。** herdr 自己的热区就是整个色块：在字**上面**那一行
  （那儿一个字都没有）点一下，它的面板照样开。只认字的话有一半面积点下去还是 herdr 的面板，
  同一个按钮就有了两种行为。
- **接走了就不能再把鼠标上报发出去**，否则两张面板一起开着，跳完 pane 回来还得再关一次 herdr 那张。
- **herdr 自己那张面板的标题也写着 `switch`**，所以色块从第 1 列开始的一律不认 —— 标题那行是
  整行同底（右上角另有一个 `close` 块）。不挡的话「关掉 herdr 的面板」那一下会被我们接走。

代价说清：herdr 那张里的「+ new workspace / + new tab / settings / keybinds / detach」这一路
就走不到了（我们这张只管「去哪儿」，取舍见 [README](../../README.zh-CN.md#面板一览--提示)）。要用它们就关掉这个开关，或者从软键条走
herdr 的前缀键。

端到端验过：窄到 64 列的真 herdr 上，关着这个开关点 switch 出来的是 herdr 那张（spaces / tabs /
menu），开着点出来的是面板一览、而且**一个字节都没往 herdr 发**；herdr 那张开着时点它的标题不会
被接走（认到的色块从第 1 列开始，直接不认）。

### 手机上怎么复制 / 粘贴

先说结论：手机上要**两个软键**（设置 →「软键条」→ 载入预设，「网页端动作」组里的
**📋 取** 和 **📥 粘**，拖到条上）。原因是下面两条，一条比一条反直觉。

**第一条：herdr 复制到的是「跑 herdr 那台机器」的剪贴板，不是手机的。**

手机上长按拖选（那一下会被翻成鼠标拖动发给 herdr，配上 herdr 自己的 `copy_on_select` 就是
一次复制），herdr 弹「copied 84 chars to clipboard」——**那 84 个字进的是 Mac 的剪贴板**
（`pbpaste` 读出来一字不差），浏览器一无所知，手机上哪儿都粘不出来。看着像「复制失败」，
其实是复制成功了、只是落在另一台设备上。

所以有了 **📋 取**（`act:clip`）：点一下，服务端读机器上的剪贴板（`pbpaste` /
`wl-paste` / `xclip`，见 `internal/clip`）交给网页，网页写进手机剪贴板。之后在手机上随便哪儿
长按粘贴都是它。

反方向是 **📥 粘**（`act:paste`）：点一下读手机剪贴板，按**括号粘贴**送进终端（多行不会被
当成一行一次回车）。触屏上没法 `⌘V`，也没法长按呼出终端的粘贴菜单（单指手势被接管了），
这个键是唯一的入口。

**为什么不能做成一个「自动同步」**：浏览器只在**用户手势**里给读写剪贴板，定时器里偷偷做
一律被拒 —— 而且是静默的。所以两个方向各要一次点击，这一下是浏览器的硬要求，不是没做。

触屏上**选不了字**（单指手势整个被上面那套接管了），所以另一条复制路径是 **herdr 自己的
COPY 模式**：`ctrl+b` 前缀进去，`hjkl` 选、`y` 复制。它走 **OSC 52** —— 终端里的程序把文本推给
网页，网页再写系统剪贴板。

**但浏览器不一定让写，而且以前是静默失败的。** 两条限制叠在一起：`navigator.clipboard` 只在
安全上下文里存在（局域网 http 上压根没这个对象），而且手机浏览器要求这一次写发生在**用户
手势**里。COPY 模式和「选中即复制」的触发点都不是点击，于是在手机上被拒 —— 屏幕上选区好好的、
一句提示都没有，剪贴板里还是上一次的东西。

现在写不进去就在底部出一条**「点一下复制」**：那一下点击本身就是手势，按一下就进剪贴板。
连 `execCommand` 也被拒的话，它把文本摊在一个**已经全选好**的框里，长按 → 「拷贝」。

还有一个**桌面上也会踩**的坑：**标签页不可见时 Chrome 让 `writeText` 那个 promise 永远挂着**
（实测 26 秒既不 resolve 也不 reject，剪贴板也确实没变）。光 `await` 的话「写不进去」永远发现
不了，所以那一步有 1.2 秒上限，超时就当失败、往后面两条路走。

两条相关的：

- **「选中即复制」是鼠标那一档的设置**，触屏上没有选区，手机上开它不起作用。
- 想在电脑上看那条提示长什么样：URL 上加 **`?nocopy=1`**，两条写剪贴板的路都当成失败
  （和 `?poll=` / `?push=` 一样是调试参数）。

为什么要这么绕：xterm.js 只把 `wheel` 翻译成鼠标上报、完全不管 touch，所以 herdr 这种「占着备用屏幕（本地没 scrollback 可滚）+ 开了鼠标上报」的程序在手机上两头都不响应，彻底滚不动。而点击和长按又都会落到隐藏 textarea 上，浏览器顺手就把键盘顶出来 —— 在 TUI 里十次里有九次只是想点个 pane，不是想打字。

做法是在 `touchstart` 上**无条件** `preventDefault`（单指手势），一次性掐掉聚焦、长按气泡、双击缩放和浏览器补发的兼容鼠标事件，然后自己在 `touchend` 里按位移和时长把手势分成上面几类。

**为什么连「没有鼠标上报」的时候也要吃掉**：不吃的话浏览器会补发兼容鼠标事件，xterm 当成「按下 + 拖选」——手指一滑变成选中文字、终端一动不动（还没 attach herdr、或者 pane 里跑着不收鼠标的程序时必现）。触屏上想滚屏远比想选字常见，所以这里选滚屏。代价：触屏不再能拖选（要复制用桌面鼠标，或者 herdr 自己的 COPY 模式），点一下也不再由浏览器顺手聚焦 textarea，改成自己在 `touchend` 里 focus。

**手势时长用事件自带的时间戳**（`e.timeStamp`），不是处理函数里的 `Date.now()`。终端忙着重绘时定时器和事件派发都会被推后，实测一次 60ms 的点击在处理函数里量出来是 994ms，于是被「超过 500ms 算长按，什么都不做」挡掉 —— 表现就是「输出一多点哪儿都没反应」。事件时间戳是事件产生时打的，不受处理延迟影响。

**换 pane 不靠盲敲**：顶栏 ▦ 或软键条上的 `act:panes` 开「面板一览」，点一行直接跳过去并铺满
（见 [README](../../README.zh-CN.md#面板一览--提示)）。按键那条通道只能表达「下一个 tab」这种相对导航，而中间每一步的屏幕正好都是
手机上读不了的那个平铺状态。

连上时也不自动抢焦点（触屏设备），否则一连上键盘就顶出来。要打字：点软键条最左边的 ⌨（`act:kbd`），或顶栏上那个「系统键盘」。键盘状态跟着 textarea 的 focus/blur 走，所以用户自己收起键盘时按钮高亮也会跟着灭 —— 但这一条不是白送的：安卓上用返回键 / 系统手势 / **输入法自己那个「收起」按钮**收键盘都**不 blur 页面元素**，灭掉那个高亮靠的是「视口长回去了就把焦点摘掉」那条补救（`App.tsx` 的 `sawRoom`），而它要下面那个键盘判据真的动得起来。判据坏了的表现就是「⌨ 一直亮着，要点两下才能把键盘叫回来」。

**顶栏在手机上收成一行**：状态只留那个彩点（完整文字进 `title`）、连上之后不显示「连接」、字号 `A−/A+` 和明暗 `◐` 挪进设置 →「终端」页。七个图标在 393px 上排不下，折成两行就白吃掉 ~36px（约三行终端），而这三个都是一次调完的东西。

**键盘一弹起来，顶栏整条收掉**，只留 8px 的一条缝（点一下放回来）。那一刻可见高度只剩 ~430px，而顶栏里的东西那时候一个都用不上 —— 正在打字的人要的是软键条和发件箱，「连接」是连之前的事。收起是临时的：手动点开只管这一次，键盘一收就自动恢复常态，不留状态（否则下次打字时顶栏在不在全靠碰）。

判断键盘弹没弹用的是 **visualViewport 被压掉多少**（`hooks/useKeyboardUp.ts`，阈值 0.8），不是「xterm 那个隐藏 textarea 聚焦了没有」：这个项目最常见的姿势是**在发件箱里口述**，那时候焦点在发件箱上，终端那边一无所知，而键盘照样占掉半个屏幕。两个信号一起用（对着终端打字时前者不动、后者认得出来）。认不出来也不影响正确性 —— 那儿就退化成「顶栏不收」。

**基准是「这个朝向上见过的最高那次」，绝不能是 `window.innerHeight`。** 原来就是拿 innerHeight 比的，而 viewport meta 里有 `interactive-widget=resizes-content`（见下一段）—— 它的语义正是「键盘同时缩布局视口」，于是安卓上 innerHeight 跟着 visualViewport 一起变矮、比值恒等于 1，**这个信号永远是 false**。失败是完全静默的，而且 **iOS 上照旧是对的**（iOS 从不缩布局视口），所以只在安卓上现形：顶栏不收，上面那条「收起键盘就摘焦点」的补救也等不到触发，⌨ 那个键一直亮着、要点两下。基线**只往上取不往下修**（进出一次全屏那几十像素在 20% 阈值以内，不会误判），转屏时按「宽度变没变」作废重量。**也别改用 `navigator.virtualKeyboard`**：它的 `boundingRect` / `geometrychange` 只在 `overlaysContent = true` 时才有值，而那是「键盘谁都不缩、你自己让开」的模式，换过去等于把 `--vvh` 那条路整个重写。

**虚拟键盘不会再盖住内容**：页面高度跟 `visualViewport` 走，并给 viewport meta 加了 `interactive-widget=resizes-content`。光重排终端不够 —— iOS 的键盘**从不**缩布局视口，`height:100%` 指的是没缩过的那个，键盘会直接盖住软键条和发件箱。

**但这套不是每个浏览器都认**（实测某些国产浏览器里页面高度纹丝不动，发件箱照样被埋一半），所以底下那块能用手拖，不依赖浏览器行为。

## 底部面板

发件箱和软键条是**同一块面板**（`web/src/components/Dock.tsx`）：一套边框、一个宽度，一次调完。

以前它们各管各的 —— 发件箱能抓着 ⠿ 从底部「撕」下来变成浮动面板（自己一套位置 / 大小 / 边框），软键条自己一套左右留白和高度。两块叠在一起就是两条边框、两种宽度、两套把手，看着像错位的两层，而「把底下这一坨从输入法上挪开」得分别调两次。现在整块一起缩：

- **左 / 右两条侧边**左右拖，改那一边的边界（横向改宽度）。输入法连着它那圈工具条常常压住半边屏幕，把整块面板缩到剩下的空地上，比整条通屏挤在键盘底下有用。
- **键那一区上边缘的三个把手是两轴的**：上下拖 = 软键条多高（**最多半屏**，放不下的部分上下滚），左右拖 = 左边那个动左边界、右边那个动右边界、中间那个整条平移（宽度不变）。每个方向都有 3px 死区，只想横着拖不会顺手把高度锁成定高。
- 软键条按键**换行**排（不再是一条横向滚动的长龙）。没拖过高度是自动的、封顶两排（不留空白）；拖过之后是定高 —— 用户明确要求「更高」就别自作聪明缩回内容高度。任意把手**双击复位**（宽度和高度一起）。
- 面板里的东西按**面板自己的宽度**折行（`@container` + `@max-3xl:`），不是按视口宽度：缩到半屏之后视口还是那么宽，按视口算的话发件箱那排控件会挤成一团。
- 左右留白换了个存储键（`dockInset`，旧的 `softkeysInset` 不再读）：以前那份只缩键那一条，现在缩的是整块，语义不一样 —— 直接套过来的话升级后一开页面会发现发件箱莫名其妙只剩半屏宽。

**手机竖屏（< 440px）是另一档**：一整套把手都不出，面板通屏，软键条**一行横滑**、键小一号（字号 13→11.5px，高 35→28px）。

- 那么窄的屏上把手是负收益：三条把手加起来 24px 高（约两行终端），而左右本来就没有空地可让 —— 那一档的输入法是整条压在底下的，不是压半边。
- 键**换行**更亏：每多一排就少一排终端。横滑只花一次划的功夫，而且常用的那几个键本来就在最前面（顺序你自己排）。要两行就在设置里明确开两行（见 [README](../../README.zh-CN.md#软键条)），每行各自横滑。
- 断点写在两处，改一个就得改另一个：`index.css` 的 `--breakpoint-phone`（给 Tailwind 的 `max-phone:` 变体）和 `hooks/usePhone.ts` 的 `PHONE_MAX`（给行内 style 和「要不要渲染把手」——这两样 CSS 盖不掉）。
- 宽度一过线（转横屏、平板、桌面）把手和存着的那份尺寸自己就回来了，两档互不影响。

### 键宽是「几格」；固定块钉在一端不滑

**宽度分三档（1 / 2 / 3 格）**，在设置 →「软键条」里选中一个键改。一格就是一个键位的宽
（`--sk-w`：44px，手机竖屏 36px），所以 2 格 = 两个键位加中间那道空。**用格数而不是「宽不宽」**
是为了跨行对得齐：一个 2 格的键和它上面两个 1 格的键左右边缘正好对上。老的 `wide` 字段留成
降级镜像（2 格以上照旧落一个 `wide:true`），升降级两个方向都不丢宽度。

### 方向键：一个格子，点开是浮窗

**弹出组**：一个键在条上**只占一格**，点一下在它上面浮出那几个键。

```
[ Esc ][ ^B ][ 方向 ]…横滑…        点「方向」→        ·  ↑  ·      ← 浮在上面
                                                     ←  ↓  →
```

为什么不摊在条上：3×2 六格在 393px 的手机竖屏上是半条屏幕（用户的原话：「一下占掉 4 个位置
太离谱」）。

**浮窗是 `position: fixed` 的,条一点都不重排** —— 这条不只是观感:内联展开会改 dock 的高度,
而那会一路触发终端重算行列 + SIGWINCH + 冻帧那一整套（见 CLAUDE.md「改尺寸会闪一下全黑」）,
点一下方向键闪一次屏。

三条边界:

- 关掉的方式:再点一次那个键,或者**点到浮窗外面**（那一下照旧透传,不吞 —— 吞掉要在
  touchstart 上 preventDefault,而那条路是这个项目一串真机 bug 的来源）。**按里面的键不关**:
  方向键要连着点。
- 判「点到外面了」只认 `pointerdown`。`click` 在触屏上会丢:浮层在 pointerup 里被卸掉,
  touch 事件的 target 钉在已脱离文档的元素上,**不冒泡到 document**。
- 视口一变（呼输入法、转屏）或者条被横滑,**重新定位,不关掉**。写成「resize 就关」是错的:
  Android 上点一下就可能把输入法顶回来（见上面 GestureTap 那条）,视口跟着一变,浮窗刚开就
  自己关了 —— 这个功能在那台机器上等于不存在。
- **组里不能再放组**（服务端挡着）。一层就够,嵌套只会变成「点开还要再点开」。

它是**定义**（在「我的按键」里），所以就是一个普通键:能拖到条上占一格、能塞进固定块、
**也能上顶栏**。

### 固定块（不跟着横滑）

**固定块**是钉在条一端的一小片**对齐网格**，**不跟着横滑**。和弹出组组合最省地方：
1 格的固定块里放一个组键 = 一个**永远不滑走**的格子，点开是方向键。它自己摊开也行：

```
[ Esc ][ ^B ][ /new ]…滑…      │   ↑        ← 这块不滑
[ ^C  ][ Tab ]…滑…             │ ← ↓ →
```

好处是那几个键**永远在拇指底下，不会被滑走** —— 手机上翻代码时最缺的就是这个。

**为什么非得单独做一块**（而不是「把 ← ↓ → 放到 ↑ 底下」）：那样也摆得出来，但**两行各自横滑**
和**跨行对齐**是互斥的 —— 滑一下其中一行，对齐当场就没了。所以对齐只能存在于「作为一个整体
参与滑动的原子」里，而最有用的那种原子就是**压根不滑**。

配置在设置 →「软键条」的「固定块」那一行。**点「方向键盘」一下就摆好**（缺的方向键从内置预设
补进「我的按键」，条顺手切成两行）—— 这一步是刻意的：不给预设的话得走「加一个 → 选列数 →
拖四次」六步，而这个功能的卖点恰恰就是那六步的结果，没人会为一个没听说过的东西先走六步。
摆好之后照样能改：列数（1–4）、钉左还是钉右、往空格（`·`）上拖就是放进那一格、块内两格互拖是
**对调**。三条边界：

- **块里每格就是一格宽**，上面那个「宽」在这儿不生效：格子是按位置排的，让某个键占两格会把
  后面的格子顶出去，整块就不是网格了。
- **它是排布，不是定义**，所以**每套一份**（平板摆 4 列、手机竖屏摆 3 列，各存一份）。格子里
  放的还是「我的按键」那些全局定义 —— 改一处按键谱两边一起变，在那儿删掉一个，格子跟着空出来。
- 这一套只有**一行**时，块的第二行会**接到第一行后面**（和条上「切回一行」同一条规则：所见即
  所得，不留「存着、不显示」的状态）。那时候谈不上对齐，但「不跟着滑」还在。

**浮动发件箱去掉了。** 想把它挪出输入法的话现在只有「整块横向缩」这一条路（这也是实际在用的那条：那台平板的输入法压的是半边屏幕）。真需要竖着挪，再把 `useFloatBox` 那套加回来 —— 但别再让它自己长一套边框。

**把手不能贴着屏幕边**（`EDGE_SAFE = 14`）。安卓手势导航把屏幕左右各一条划给了侧滑返回 / 前进，那一条系统先吃，网页连 `touchstart` 都收不到 —— 贴边的把手就是拖不动（实测）。所以把手离屏幕边不足这么多时往里让，面板里的东西跟着让出同样的内边距，免得控件钻到把手底下；面板自己已经缩进来了就不用让。数值是真机上试的：按系统标称的 24dp 让，让出来那条太宽、看着像错位，而实际有效的侧滑判定比标称窄。哪天侧边把手又拖不动了，先怀疑这个数。

**横屏一套、竖屏一套**（`web/src/lib/oriented.ts`）。同一块面板在两种朝向下想要的尺寸位置根本不是一回事，共用一份的话每次转屏都得重摆，还会把另一份覆盖掉。所以底部面板的高度和左右留白按朝向分开存，转屏就换成那一份再收边（**读**那一份，而不是把手上这份挪一挪）。朝向按宽高比判断，不用 `screen.orientation` —— 桌面窗口、平板分屏下宽高比才是真正决定布局的东西。老版本存的那份（不带朝向后缀）会在第一次读到时迁到当前朝向名下，已经调好的设置不会因为升级丢掉。

横屏比竖屏好用很多（列数够）；字号用顶栏 `A− / A+` 调；顶栏还有个**全屏**按钮，地址栏和工具条一去终端能多好几行。iOS Safari 不给网页全屏（只有视频能），那边点了会提示改用「添加到主屏幕」，从主屏打开一样没有地址栏。

## 顶栏（放哪几个按钮自己拖）

顶栏右边那排图标**放哪几个、什么顺序，是配置**，在设置 →「顶栏」页里拖：上面是顶栏、下面是
两个库（内置按钮 / 我的按键），按住拖上去就是加，拖下来（或者点 ✕）就是去掉，栏里拖是排序。
库里的方块**点一下**也能直接加到末尾 —— 「加一个」不该非得先学会拖。

和软键条同一套做法（**库在下、栏在上、拖进去**），手势也是同一份代码（`web/src/lib/chipdrag.ts`
—— 两套排布界面各写一遍拖动，就是「同一个动作两种手感」的来路）。触屏上按住 250ms 才算拿起：
这一页要能上下滚，而方块本身就是把手，不按住没法区分「滚页面」和「拖这个」。

存**服务端**（`~/.herdr-web/topbar.json`，见 `internal/topbar`），跟着人走、不用一台一台调 ——
但**放哪几个是按套分的**（上一节）：平板上八个图标、手机竖屏三个，同一个文件里一套一段。
存的是**一串按钮 id**，不是按钮的定义：按钮长什么样（图标、
名字）是内置的（`web/src/components/topbarItems.tsx`）。服务端另有一份白名单，两边必须一字不差，
有测试盯着（`internal/topbar` 的 `TestActionsMatchJS`）—— 只在一边加一个按钮的后果很难查：
编辑器里拖得上去、一存报「不认识的按钮」，或者反过来存得下去但顶栏上画不出来。

**能放的内置按钮**：面板一览 / 文件 / 发件箱 / 软键条 / 系统键盘 / 传图 / 取剪贴板 / 粘到终端 /
缩小字号 / 放大字号 / 明暗 / 全屏 / 设置。中间那四个原来只有软键条上有（`act:` 那几个），现在
顶栏也能放 —— 反过来软键条也照旧能放，两条栏是各自的配置。

### 「我的按键」也能上顶栏

第三个筐里是软键条那份**「我的按键」**：拖上去，顶栏上就多一个 mono 方块（不是图标 ——
「图标 = 内置功能、方块 = 我自己配的键」一眼分得开，而这两类点下去的后果差得远：一个开面板，
一个往 pane 里发字节）。

顶栏上存的是**引用**（`key:<定义ID>`），定义还是软键条那一份：

- 改一处按键谱（在「软键条」那页）**两边一起变**；在那儿删掉一个，顶栏上也跟着没了。
- 所以 `ctrl+b z`、`/new` 这种不用等它变成内置按钮 —— 自己配一个键，拖上顶栏就行。
- 打了 `confirm` 的键在顶栏上**照样要点两下**（关 pane 那种，herdr 那边没有撤销）。
- 粘滞 Ctrl / Alt 放上去是**饱和绿**（按下去了必须一眼看见），和内置按钮的「打开态是淡绿」
  不一样 —— 那是刻意的，见 CLAUDE.md 配色那节。

三条边界：

- **⚙ 设置删不掉**（编辑器里它没有 ✕，拖到库里会被挡回来，服务端存盘时也会补回去）。它是唯一
  一条改回这份配置的路，而配置是跟着人走的：在手机上删掉，电脑上也就没了。
- **顶栏放不下会自己横滑**，不换行、也不会藏起来。原来字号 ± / 明暗在手机竖屏是 CSS 藏掉的
  （七个图标在 393px 上排不下），现在那条去掉了 —— 「我明明拖上去了却看不见」是最难解释的一种
  行为，而横滑是手机上的软键条早就在用的做法。
- **左边那截（状态点 / session 标签 / 「连接」）不参与配置**：那不是按钮，是「这个页面对着哪个
  herdr、连上了没有」——一屏里唯一说得清这件事的地方，能删掉只会让人以为页面坏了。

## 排布分套（一类设备一套）

**排布按套分，定义共用一份。** 软键条和顶栏存服务端是对的 —— 存一次就跟着人走，不用一台一台
调。但**排布**这件事恰恰是每类设备各要一份：平板上二十个键排两行，手机竖屏上放得下五个。
只有一份的时候，平板和手机就是在互相拆台。

所以分三层（`internal/profiles`，存 `~/.herdr-web/profiles.json`）：

| 层 | 装什么 | 几份 |
|---|---|---|
| 全局 | 软键条的**定义**（「我的按键」） | 一份 —— 改一个按键谱，所有套一起变 |
| 套（profile） | 软键条 `rows`/`bar`、顶栏 `items`，以及**设置里「终端」那一整页** —— 字号、明暗、五个终端开关、键盘全屏、提示那几个 | 每套一份 |
| 设备本地 | 上次全屏为什么失败、面板尺寸位置（还要按横竖屏分）、未读游标、发件箱瞄准哪个 pane、发件箱 / 软键条显不显示 | `localStorage`，永不同步 |

全局那一层是刻意的：每套各存一份定义的话，会长出「手机上那个 ⌃B 还是老按键谱」这种最难查的
毛病 —— 你在平板上改完验过了，它就是不对。

**系统通知那个开关也跟着走**，虽然权限是每个浏览器各自的：界面上那个勾是「想要」和「给了权限」
**与**起来画的，而真弹之前 `showNotify` 还要再问一次权限 —— 所以同步过去不会变成「显示着开着、
一条都不弹」。**明暗跟系统走，但自己点过一次就钉住**：不钉的话系统一切换就把套里存的值冲掉，
下次报到又读回来，两边来回打。**发件箱 / 软键条显不显示留在本地**：那是顶栏上随手点的视图状态，
一次会话点十几次，每点一次写一趟服务端不值当。

那一行选择器摆在分页条**上面**，不做成第五个分页：「顶栏」和「软键条」两页改的就是它点名的那
一套，所以它得在你干活的时候一直看得见。**「新建」是从当前这一套复制**过来的 —— 从平板那套拷
过来再删几个键，比从零拖快得多，而这也是这个功能最常用的动作。删掉一套时，绑在它上面的设备
落回「默认」那一套，所以「默认」删不掉。

**绑定是显式的，绝不按屏幕宽度自动切。** 分屏、转屏、外接显示器都会让宽度跳变，而套里装的正是
软键条 —— 最不能在手指底下乱动的那个东西。设备类别（`pointer: coarse` + `screen` 的短边）只用
**一次**：某个浏览器第一次来、还没绑过时，拿它挑一套起点；挑完就落盘，之后再也不猜。横屏 / 竖屏
是**另一条轴**，各设备本地各存一份（`web/src/lib/oriented.ts`）—— 并进来会让套数翻倍，而朝向
当场量一下就知道，不需要人来选。

**认「这台设备」用的是浏览器自己生成的 installId**，不是 `auth` 里那个配对设备 ID：本机直连
（loopback）压根没有设备 ID，而那正是桌面上最常见的情形。它不是凭据，服务端也不拿它做任何权限
判断 —— 拿到它最多只能说「我是那台平板」，然后读到那台平板的按键排布。清掉 `localStorage`
就丢了绑定：那时候按类别重新猜一次，人在设置里再点一下就好。设置 →「设备」页里列着每个来过的
浏览器和它用的那一套，所以能**在平板上把手机那台改回去** —— 排布调坏了的那台设备，恰恰是最难
操作的一台。

文件格式上有两件事，都是为了「别把配置弄丢」：

- `softkeys.json` / `topbar.json` 每套一段放在 `profiles` 里，同时把**默认那一套镜像到顶层的老
  字段**上。老版本的 herdr-web 只认顶层，不镜像的话降级看到的就是「软键条自己恢复出厂了」，而
  那份配置明明还在文件里。冗余一份换这个，值。
- **读得宽松，写得严格。** 定义是全局的，在平板上删掉一个定义，手机那一套的条上就可能留下一个
  悬空引用：存盘时会把**所有套**条上的悬空引用一起清掉，而读的时候是丢掉认不出的那一个引用 ——
  不是整份退回出厂（那会把没坏的那一半也一起抹了）。

## 面板一览的细节

（怎么用在 [README](../../README.zh-CN.md#面板一览--提示)：点一行跳过去并全屏。这儿是排序和时间列为什么长这样。）

### 排序（可切换）

顶上那个按钮点一下换一种，记在本地：

| 排序 | 规则 |
|---|---|
| **优先级**（默认）| 按「多想让你看一眼」分档：**等你回答 > 跑完了 > 在跑 > 闲着 > 非 agent**，同一档里按最近动过排 |
| **分组** | 按 workspace 分组，组里是 tab / pane 的原顺序 —— 和你在 herdr 里看到的一样 |

状态点的颜色：**红 = 等你，绿 = 跑完了，黄 = 在跑**，闲着是灰点。「在跑」用黄不用绿，和 herdr
自己 agents 栏那个黄点一致；绿留给「跑完了」（通用约定，一眼知道是好事）。只有闲着不给颜色 ——
一列点全是彩的就没有重点了。

`在跑` 单独一档。一开始把它和 `闲着` 合成了一档（理由是两个都不需要你，谁在前面没有客观
答案，交给「刚动过」去定），实际用起来不对：黄点那个正在跑的会被十几个闲着的埋掉，而列表里
最想一眼看到的恰恰是它。`等你` / `完成` 两档在行上额外挂一个小标签，别的状态只有那个点的
颜色 —— 每行都塞标签就没有重点了。

**同一档里认 `state_change_seq`**（herdr 里的全局递增计数，每次 agent 状态变化推高一格），
不认时间。因为 herdr 的 API 里**一个时间戳都没有**：`agent.list` 只给这个计数，事件里也不带
时间。计数一直是对的，所以排序一直是对的。

### 「3 分钟前」那一列

时间是 **herdr-web 自己盯着状态变化打的**（`internal/agentwatch`：订一条
`pane.agent_status_changed`，收到就记 `time.Now()`）。所以：

- **第一次跑的时候这一列是空的**，随着一次次状态变化填回来。空着是实话 —— 那个变化发生在
  开始盯之前，没法知道是什么时候，编一个时间比空着糟得多。列表底下会说明这一句。
- **按 `terminal_id` 存盘**（`~/.herdr-web/agent-seen.json`），所以 herdr-web 自己重启
  （升级、改配置）不丢时间。不能按 `pane_id` 存：那是 herdr 里的位置编号，pane 一开一关就
  重新分配给别人了，会张冠李戴。herdr 重启之后终端 id 全是新的，旧记录自然对不上 —— 存盘时
  只写这会儿还在的终端，文件自己就不会长胖。
- **状态不存盘**，只存时间。存了状态的话，重启后拿旧状态一比就会把「停机期间变的」记成
  「刚刚变的」。
- 订阅没连上（herdr server 没在跑）时，列表底下会说一句，免得空着的时间列看着像坏了。
- 显示用 `3m` `2h` `4d` 这种紧凑写法（不到 45 秒算「刚刚」），完整时间在 title 里。手机上这一列
  只有几十像素，「3 分钟前」四个字放不下。

几个细节：

- **pane id 在手机上也照样显示**。一个 tab 里分了两个 pane 时，两行的 tab 标签和 cwd
  一模一样（实拍见过），id 是唯一分得开的东西。
- 第二行给的是 **agent 自己写的会话标题**（Claude Code 那个「图片识别」之类），没有才退回
  cwd —— shell pane 的标题只是 `user@host:path`，不如路径。
- **跳完不自动聚焦终端**（手机上那一下会把系统键盘顶出来，而刚跳过去多半是要看）；宽屏上顺手聚上。
- 投稿目标不用管：默认那条「跟随 herdr 当前 pane」自己就跟过去了。本地有草稿时目标仍然锁在
  原来那个 pane 上 —— 为 A 写的话不该因为你去 B 看了一眼就投给 B。
- 「全屏」开关记在本地（`localStorage`）。手机上默认开：多 pane 平铺读不了，去了不放大等于没去。
- `zoomed` 是**整个 tab** 的状态，不是某个 pane 的（herdr 放大的永远是当前焦点 pane）。
  所以「这个 tab 只有一个 pane」会回 `zoomed:false`，那不是失败，界面上单独说一句。

## 提示卡片的细节

（那段话**怎么抽出来**的在 [COMPOSER.md](COMPOSER.md)。这儿是什么时候弹、弹几张、红点怎么算看过。）

### 什么时候弹

| 变化 | 弹不弹 | 为什么 |
|---|---|---|
| → `blocked`（等你回答）| **弹**，而且不自动消失 | 它是真的停在那儿等你。卡片自己飘走就又回到「不知道谁在等」了 |
| `working` → `idle` / `done`（跑完了）| 弹，12 秒后自己收掉 | 只是通知，错过也不影响什么 |
| → `working` | 不弹 | 那多半是你自己刚投进去的，弹一下纯属回声 |
| `blocked` → `idle` | 不弹 | 你刚回答完，它这会儿正要开工 —— 报「跑完了」是假话 |

**状态稳 2.5 秒才算数。** claude / codex 干活时状态会短暂抖回 idle，不防抖的话一个长任务
能弹出十几个假的「跑完了」；而 `pane.read` 的快照本身还有一帧延迟，立刻读会读到上一个任务的
尾巴。防抖那 2.5 秒里状态又变了（`idle → blocked` 是常见的一串）就报**最后**那个，只弹一条。

**herdr 停机后重新连上时不补弹。** 那一刻对底会发现一屏 pane 的状态都和停机前不一样，可那些
变化是「这半小时里发生的」，当场弹成一片「刚刚跑完了」就是在编时间 —— 和「3 分钟前」那一列
不肯给旧变化编时间是同一个道理。代价是重订阅那 800ms 窗口里的变化会漏报一条。

### 卡片

- **点一下 = 跳过去**（顺带全屏，和面板一览点一行同一个动作、同一个「全屏」开关），
  跳完那张卡自己收掉 —— 已经去看了，留着只挡视线。
- 右上角最多同时挂 **3 张**，多出来的收成一行「还有 N 条 · 去面板一览」。
- **挂多久在设置里调**（5 秒 / 12 秒（默认）/ 30 秒 / 1 分钟 / 一直挂着）。
  「等你回答」那种**不受这个管**，永远挂着。
- **「等你回答」排在最上面**，然后才按新旧。不按纯时间排是因为两种卡的寿命不一样：
  「跑完了」十几秒就自己走了，而「等你回答」一直挂着 —— 按时间排的话，一条刚来的
  「跑完了」会把那个真的在等你的顶下去，而它恰恰是唯一需要你动手的那张。手里攒满了
  也是先丢「跑完了」那种。
- 面板开着的时候整摞先让开：那几块浮层就在同一个角上。

### 红点

- 在顶栏的 ▦ 上；软键条里 `act:panes` 那个键上**也有一个** —— 手机上键盘一弹起来顶栏整条
  就收掉了，而那正是你在跟 agent 说话、最该知道「另一个在等你」的时候。
- **开面板一览 = 看过了**（红点唯一的灭法）：那儿就是看这些变化的地方，优先级排序会把
  「等你 / 完成」顶到最前面。收掉单张卡片**不算**看过 —— 那只是嫌它挡着。
- 记在 `localStorage`（记的是 seq，不是条数），**刷新页面不丢**：手机上刷一下红点就没了的话，
  这个提示等于白做。命名 session 各记各的（那是另一个 herdr）。
- **嫌那个点扎眼可以关**：设置 →「终端」页最后一条「面板图标上的红点」。关掉只是不画那个点，
  右上角的提示卡照常出 —— 两件事分开：点是一直挂在那儿的，卡是自己会走的。存在本地，
  一台设备一份。整套提示要关是服务端那侧的 `HERDR_WEB_NOTICE_MS=0`。
- **打开页面时只点红点、不补弹卡片**：那些变化可能是半小时前的，弹出来像刚发生一样就是编时间。

### 系统通知

设置 →「终端」页的「系统通知」打开（**那一下必须是你自己点的** —— 浏览器只在用户手势里给
权限弹窗）。开了之后，**页面在后台 / 锁屏时**新提示会走浏览器的系统通知；点通知会把页面拉
回前台并跳到那个 pane。

- **默认只在你没看这一页时弹**。判据是 `document.hidden || !document.hasFocus()` ——
  **不能只看 `hidden`**：macOS 上你切到别的 app、Chrome 只是失焦，标签页仍然算 visible，
  于是「切出去干别的」这个最主要的场景一条都不弹（第一版就是这么漏的，报上来的现象是
  「系统通知根本没出来」）。想让它前台也弹，设置里有「我正看着这一页时也弹」。
- **「试一下」按钮**：不看开关也不看在不在看这一页，当场弹一条。「到底卡在哪」（权限没给？
  系统专注模式？iOS 没装到主屏？）光靠猜是猜不出来的，弹一次就知道了。
- **同一个 agent 只占一条**（通知的 tag 用 `terminal_id`），新的替换旧的，不在通知中心堆成一摞。
- **手机上**：Android Chrome 在普通标签页里就行；**iPhone / iPad 必须先「添加到主屏幕」**，
  从主屏那个图标打开（Safari 标签页里的网页拿不到通知权限，iOS 16.4+ 才有）。
- **iPhone / iPad 必须「添加到主屏幕」**从主屏打开才有通知；Safari 标签页里的网页拿不到权限。
  而且 iOS 上 `new Notification()` 这个构造函数根本不存在，只能走 service worker 的
  `showNotification` —— 所以打开这个开关时会注册一个 `sw.js`（**不打开就没有**）。
  那个 SW **不缓存任何东西**（连 fetch 事件都不听），只处理通知点击：终端页面上挂一个会拦
  请求的 SW，只会制造「明明改了却没生效」这类查半天的怪事。
- **页面关掉就收不到**。真正的「浏览器关了也能收到」要 Web Push（VAPID 密钥 + 订阅落盘 +
  服务端主动推），是另一整套东西，这一版没做。
- http 上（既不是 https 也不是 localhost）浏览器不给通知权限，开关会灰掉并说明原因。

### 边界

- `agent_status` 判断不了「正开着对话框」（实测同一个选择器，一次报 `idle` 一次报 `blocked`，
  见 [HERDR-API.md](HERDR-API.md)）。所以偶尔会有一条问话被弹成「跑完了」—— 卡片上的内容
  仍然是那个问题，状态标签错、跳转是对的。
- 抽取规则跟着 claude 现在的界面走。它改版之后可能抽出一段怪文字；那时候状态和跳转仍然
  照常，testdata 里换一份新抓屏 + 调规则即可。
- 关掉整套提示：`HERDR_WEB_NOTICE_MS=0`（前端不再轮询，也不画红点）。
- **状态是「轮询保底 + 事件加速」凑出来的**，不是只听事件。实测（真机）：herdr 只对**看得见的**
  pane 推 `pane.updated` —— 给背景 workspace 里的一个 agent 投一句 hi，`pane.get` 6 秒就报
  working、13 秒报 done，而事件流里**第一条事件 40 秒后才来**。而背景里那些恰恰是提示最该管
  的（你看得见的那个用不着提示）。所以另有一条 3 秒的 `pane.list` 轮询保底，事件只负责让你
  正看着的那个几乎实时。
- **短任务 herdr 常常不报 `working`**：戳一个 agent 说句 hi，状态是 `idle → done` 直接过去。
  所以 `done` 和 `blocked` 一律弹，不要求「必须从 working 来」—— 早先那版要求了，于是短任务
  一条提示都弹不出来（单测全绿，端到端才发现）。

## 认路径的几个坑（都在 `web/src/term/paths.ts` 里）

- **路径会被折行断开，而且折行的不止 xterm。** 80 列的 pane 里一条长路径就是跨两行的，
  所以先把逻辑行拼回来再找。两种折行都要认：xterm 自己折的（`isWrapped`，普通 shell 里的
  长行），和 **TUI 自己折的** —— herdr 的 pane 是绝对定位重画的，外层 xterm 收到的每一行
  都是独立一行，`isWrapped` 永远是 false。只认前者的话，手机上被 agent 折成两行的长路径
  还是只找得到前半截：点下去报「没有这个文件」，而屏幕上那条下划线看着挺正常。
  后者的判据三条，缺哪条都是**静默**出错（拼错的链接看着和好的一模一样）：

  1. **顶到内容区右边界，一个尾随空格都不剩。** Claude Code（Ink）折行走的是 `wrap-ansi`
     的 `hard: true`，路径这种断不了词的长 token 会正好切在列宽上；正常断句断在空格上，
     右边一定剩几格。框线里（`│ 内容 │`）内容和竖线之间有一格 padding，所以有竖线时容
     一格 —— 但**这一行只读到最后一个字符为止**，把那格 padding 读进来就等于往路径中间
     插了个空格，白拼。
  2. **两行的内容全落在同一条带子里。** 分栏时另一半 pane 的内容在带子外面，一拼就把那
     半边整行丢掉，那一行上别人的路径当场点不动。宁可这条不拼。
  3. **被切开的那个词真的一行装不下。** wrap-ansi 只在「一个词比整行还长」时才切开它，
     装得下就整个挪到下一行。只靠第 1 条的话，「英文单词正好压在边界上」会被当成折断 ——
     拿 14 个真 pane（807 行）扫过，正好压线的有 3 处（`…whether` / `…deploy to` /
     `…that`），加上这条之后一处都不误拼。
- **pane 的竖线要当终止符。** 路径最后一个字紧挨着 `│` 时，不挡的话它会被吞进路径里变成
  `/tmp/a.pn│`，下划线一直画到分隔线上。
- **拼回来不能用 `translateToString`。** 有中文时它返回的字符数和格子数对不上，
  下标映射回坐标会整条错位 —— 下划线画在半个词上、点下去取到另一段。所以逐格读。
- **中文标点得当终止符。** 实测 agent 打的是「生成好了 /tmp/a.png。相对的 …」，中文和
  路径之间没有空格 —— 不挡 `。` 的话整段 `a.png。相对的` 会被当成一个路径，点开报
  「没有这个文件」而下划线看着完全正常。汉字照样放行（`/tmp/图表.png` 是合法文件名）。
- **光秃秃的相对路径必须带扩展名。** 只数斜杠不够：`2026/08/21` 有两个斜杠，按「两段
  就算」会被画成链接。`and/or`、`100/200` 同理。有根的（`/usr/local/bin`）不受这条限制。
- **被 `…` 截断过的路径直接不给链接。** 认不出就是认不出，别猜一个短的出来然后报
  「没有这个文件」。

## 实测结论：herdr 在浏览器里是能正常用的

herdr 启动时会请求这些终端能力（用 PTY 抓下来的），对照现在的实现：

| 序列 | 用途 | 状态 |
|---|---|---|
| `CSI ? 1049 h` | 备用屏幕 | xterm.js 原生 |
| `CSI ? 1000/1002/1003 h` + `1006` | 鼠标点击/拖拽/移动 + SGR 坐标 | xterm.js 原生 |
| `CSI ? 2004 h` | 括号粘贴 | xterm.js 原生 |
| `CSI ? 1004 h` | 焦点进出上报 | xterm.js 原生 |
| `CSI ? 2026 h` | 同步输出（防画面撕裂） | xterm.js 原生，另加了重绘看门狗（见下） |
| `OSC 8` | 终端超链接 | xterm.js 原生，点击在新标签页打开 |
| `OSC 52` | 程序写系统剪贴板 | ClipboardAddon |
| `OSC 10;? / 11;?` | 查询前景/背景色（判断明暗） | xterm.js 不回，**本项目自己回** |
| `CSI ? 2031 h` | 主题变更通知 | xterm.js 不支持，**本项目自己发** `CSI ? 997 ; 1/2 n` |
| `CSI > 7 u` | kitty 键盘协议 | xterm.js 不支持，**本项目补了消歧子集** |

那几个开关在顶栏最右的 ⚙ →「终端」页里。**「程序请求的终端能力」那张列表去掉了**：它是当初补协议时的调试视图，日常没人看（能力本身还照样记着，`DEC 2031` 的主题通知要用）。
