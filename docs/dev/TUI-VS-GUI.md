# 一件事该留在 TUI 里，还是该在网页这边另做一层

**默认留在 TUI。** herdr-web 是「浏览器里的 herdr」—— 它接的是整个 TUI，网页这边每多一块
界面，就多一个要维护、要鉴权、要在手机上调、还可能和终端里那份说法不一致的东西。

只有当下面某一条**真的成立**时才另做：小屏 + 触屏把 TUI 本身弄坏了，或者那件事**根本不在
终端里**（相机、系统剪贴板、通知）。`git diff` 是最标准的一个例子，这份文档就从它说起。

> 这份是**判据**。具体每块界面为什么长成那样在 [MOBILE.md](MOBILE.md)、
> [OUTBOX.md](OUTBOX.md)、[SECURITY.md](SECURITY.md) 里；这儿只回答「要不要做」。

## 0. 为什么默认是 TUI

- **一份实现，两处都能用。** 同一个 herdr，PC 上和手机上是同一套操作、同一份状态。
  网页这边另做一层就是第二套，两套之间的差异是要靠人记住的。
- **键盘是最快的路径。** 坐在电脑前时，任何一个「点一下」的界面都比一个快捷键慢。
- **agent 的上下文在那儿。** pane 里那个 TUI 是 agent 自己的界面，我们复制一份出来就得
  跟着它的版本跑。
- **网页那一侧不是零成本。** 每加一块界面都要各自处理：认证（它能从公网点到）、
  能不能关掉、手机上的手势和键盘、后台标签页里那些不跑的东西（rAF / IntersectionObserver）。

所以下面这些判据的门槛应该定得**高**：不是「网页上做出来更好看」，而是
「**在手机上，TUI 那条路已经不成立了**」。

## 1. 六条触发条件（成立一条就值得做）

### ① 小屏放不下二维内容，而终端不能折行、不能重排

终端里一行就是一行。手机竖屏 40 来列，而 `git diff` 每行前面还要先占掉一格 `+`/`-`：
长行要么被切掉，要么整屏横滚。**颜色也只有三档**（红 / 绿 / 白），一整行红配一整行绿，
改了哪个词得拿眼睛一格一格扫。

网页这边能做而终端做不到的正好是这三件：**折行**、**按词高亮**（只把真正变了的那截标出来）、
**按文件分开点着看**。这就是「改动」那块界面存在的全部理由 —— 别往里加第四件。

### ② 只能表达「相对导航」，说不出「跳到那一个」

快捷键条发的是**按键**，而按键只能说「下一个 tab」「往右一格」。「让 `w5:p3` 全屏」这句话
用按键说不出来 —— 手机上换个 pane 得盲敲一串，而中间每一步的屏幕，恰恰都是
「未放大的多 pane 布局」那个在手机上根本读不了的状态。

herdr 的 socket 这一层是**按 pane_id 寻址**的（`pane.zoom` 带 pane_id 就能跨 workspace + tab
一次切过去），所以「面板一览」点一行就到。**能力在协议里，只是键盘表达不出来** —— 这一条
是最容易被忽略的触发条件。

### ③ 要在几十上百个里挑一个

列表 + 筛选 + 搜索，在有键盘的地方是 `/` 加几个字母，在手机上没有等价物。
面板一览（几十个 pane）、文件浏览（一个目录几千个文件）、改动清单（一次改动二十个文件）
都是这一条。

### ④ 那件事根本不在终端里

- **相机 / 相册**（传图）：终端里没有这个东西。
- **剪贴板**：herdr 的复制落在**跑 herdr 那台机器**上，手机上按什么都拿不到 ——
  只能由服务端那侧读出来（`internal/clip`）。
- **语音输入**：那是系统输入法的能力，而且要能「说一段、框选重说、攒够了再投」。
- **系统通知 / passkey / 全屏 / 明暗**：浏览器和操作系统的能力。

这一条和屏幕大小无关，PC 上同样成立。

### ⑤ 要在你没看着的时候告诉你

TUI 只在你正盯着它的时候存在。「某个 agent 在等你回答」「工作区又变了」这类事，要在
锁屏、切到别的 app、终端根本没打开的时候也能到你眼前 —— 红点、提示卡、系统通知都是这一条。

### ⑥ 触屏上，终端里的「滚动」不是滚动

网页里滚动是浏览器原生的：惯性、回弹、滚动条、随手一甩几百行。终端里的「滚」是把按键
（或鼠标滚轮上报）发给对面的程序、等它**重画一整屏**回来 —— 一次往返加一次全屏重绘，
手指和画面之间永远差一拍，而且没有惯性可言。翻页更糟：pager 要靠快捷键条上的方向键点。

手机上还有一笔额外的税：**呼一次输入法就会重排**，而重排 = 清画布 + `SIGWINCH` +
herdr 清屏重画（所以我们才要那套「冻帧」，见 [MOBILE.md](MOBILE.md)）。同一份内容放在
网页的普通滚动容器里，这些全都没有。

## 2. 反过来：这几种必须留在 TUI 里

### ① 会改状态的事

`git add` / `commit` / `checkout`、开关 pane、跑命令 —— 出问题时你要看得见输出，而
「一个从公网点得到的按钮」和「在终端里敲一行」的风险完全不对称。所以那块 diff 界面是
**只读**的，没有 add / commit / checkout，也不打算有（见 [SECURITY.md](SECURITY.md) 那节）。
同理，面板一览点一行只是让 herdr 切焦点，**不增删改 pane**；文件浏览、改动清单也只是
**入口**，要动就回终端里动。

### ② PC 上键盘已经够快的事

判据是「**只在手机上**不成立」。要是一件事在电脑前用得挺顺，那它需要的是一块网页界面，
**不是**去改 TUI —— 改 TUI 会让电脑那头也跟着变。

### ③ 要 agent / pane 内部状态才做得了的事

那是 herdr 自己该管的。网页这边只能拿到 socket 给的那些 + 屏幕上那些字。

## 3. 动手之前过一遍这六个问题

1. **它在 PC 上也不好用吗？** 是 → 该考虑扩 TUI，不是加网页界面。
2. **数据能不能只读地拿到**（herdr socket / 磁盘 / `git`），不用人手同步？
3. **能不能不读屏？** 读屏（`internal/composer`、`internal/agentwatch`）是这个项目最贵的一
   条路：错了**不报错**，只能靠真机抓屏钉住。能走数据路就别读屏 —— 改动那块走的是 `git`，
   所以它稳。
4. **要不要按秒轮询？会不会跟 agent 抢那台机器？** 已经踩过两次：`git status` 默认会写
   index、抢 `.git/index.lock`（`--no-optional-locks`）；一台机器上开着几十个 pane，
   一拍几十次 fork 换一个小角标不值当。
5. **关得掉吗？** 每条路都要有开关，而且关掉之后**连按钮都不画**
   （`HERDR_WEB_FILES=0` / `HERDR_WEB_GIT=0`）—— 点开一片报错比没有这个入口更糟。
6. **它值不值一格顶栏？** 顶栏是**用户自己配的**（能力清单里一行 + 一行，见
   `internal/capability`）—— 加一件事很便宜，但每件事都要能被删掉。

## 4. 已经做出来的那些，各自是被哪一条触发的

| 网页这边的界面 | 触发的条件 | 留在 TUI 的部分 |
|---|---|---|
| 改动（git diff） | ①⑥ + ③ | 所有会改仓库的操作 |
| 面板一览 | ②③⑤ | pane 的增删改、布局 |
| 文件浏览 / 看图 | ③④（图是像素，终端里显示不了） | `cat` / 编辑 |
| 发件箱（语音投稿） | ④（语音 + 攒稿） | agent 自己的输入框，我们只是把字送进去 |
| 传图 / 取剪贴板 / 粘到终端 | ④ | —— |
| 提示卡 / 红点 / 系统通知 | ⑤ | —— |
| 快捷键条 | ④（手机上根本没有 Ctrl / Esc / 方向键这些键） | 它发的就是按键，语义完全在 TUI 那边 |

一个反例：**没有**「网页版的 workspace 管理器」，尽管协议给得到。理由是第 2 节 ①② ——
它会改状态，而在电脑前 herdr 自己那套快得多。

## 5. 真做的时候守这几条

- **只读优先。** 要改东西就把它送回终端：把路径投给 agent、把命令敲进 pane。
- **走数据路，别读屏**（第 3 节 ③）。
- **一件事 = 能力清单里一行 + 一行**（`internal/capability` + `web/src/capabilities.tsx`），
  顶栏 / 快捷键条 / 两个编辑器白拿到。
- **可关**，而且关掉之后入口一起消失。
- **别跟 agent 抢那台机器**：能缓存就缓存、页面不可见就别问、一次只跑一个。

## 6. 那什么时候该去扩 herdr 的 TUI（比如插件）

上面反过来就是：

- 这件事在 **PC 上也需要**（不是「小屏才不成立」）；
- 它**要改状态**，或者要 pane / agent 的内部状态；
- 它需要**就地显示**在 pane 里，不打断你正在看的那一屏；
- 键盘就是它最自然的操作方式。

这类东西做进网页只会得到一个「电脑上没人用、手机上又改不动状态」的半吊子界面。
