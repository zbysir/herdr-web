**一句话**：云上跑一个**只转发密文**的中继（`herdr-relay`），主机上的 herdr-web 主动连上去；
手机打开 `https://mac.h.example.com`，中继按 SNI 把这条 TLS 原样转给那台主机。**TLS 在主机上
终止，页面也是主机发的** —— 中继手里没有证书私钥、没有设备表、没有 passkey，被整台拿下也只能
断你的网，看不到也改不了内容。App 里再加一层：同一个地址，在家时**换路**直连主机，不换 origin。

和 frp 那一档的关系：原来写的是「并列，不替换」，**2026-10-23 改成替换**：frp / 公网口
（`PUBLIC_PORT`）/ `TLS=proxy` / `TRUST_PROXY` 一起下线，公网入口只剩中继（理由就是 §1.1：前面那层
解密 = 它被拿下就是整个终端）。frp 要你自己配 frpc / frps、自己管公网端口和
`PUBLIC_URL`；中继把这些收成「主机上跑一条命令」。底下的安全模型（TLS 在主机上终止、公网走
单独的监听）和 [SECURITY.md](SECURITY.md) §8 是同一套，没有新开的豁免。

## 1. 先把「云端」能拿到什么说死

用户担心的是：「passkey 这些现在存在电脑上，放到云端泄露了怎么办」。答案是**不放**。这份
设计的出发点就是：**按「中继那台 VPS 已经被人拿下」来设计**，看它还能干什么。

| 东西 | 放在哪儿 | 中继被拿下时 |
|---|---|---|
| 设备表、passkey 公钥、配对码、交接令牌 | **主机**（和现在一样） | 拿不到 |
| 这台主机的 TLS 证书私钥 | **主机** | 拿不到 |
| DNS 的 API token（签证书用） | **主机**（和现在 ACME 那条一样） | 拿不到 |
| 终端画面、按键、chat、文件内容 | 只在 TLS 里过一下 | 只见密文 |
| 页面的 JS | **主机**发的 | 换不了（见 §1.1） |
| 「哪台主机叫什么名字 + 它的公钥」 | 中继 | 泄露了没用：公钥本来就是公开的 |
| 谁在什么时候连了多久、多少字节、SNI 里的主机名 | 中继看得见 | **元数据泄露，接受** |

中继被拿下之后真正能做的只剩：**断网**（DoS）、**看元数据**、以及**去签一张你那个域名的证书来
做中间人** —— 最后这条是唯一的真威胁，§1.1 专门堵它。

### 1.1 为什么不能让中继终止 TLS（最容易走歪的一步）

最省事的做法是中继拿一张 `*.h.example.com` 的证书、终止 TLS、再反代到主机 —— Cloudflare
Tunnel、ngrok 默认都是这么做的。**这里不能这么做**，理由不是「流量会被看到」那么简单：

- **网页上的端到端加密是假的，只要页面是中继发的。** 中继能改 JS，改过的 JS 想读什么读什么
  （终端画面、按键，以及**替你按 passkey** —— WebAuthn 防钓鱼防的是别的域名，不防同一个
  origin 里的恶意脚本）。所以「中继只转密文」必须是**整条 TLS 原样转**，页面从主机来。
- 于是中继能用的只有 **SNI 路由**（读 ClientHello 里那一个明文字段，后面的字节一个不碰）。
  这和 frp 的 `type = tcp` 是同一个形状，SECURITY.md §8 第 1 条选它也是这个理由。

剩下那条：**中继占着这个域名的 IP，它能自己去 Let's Encrypt 用 HTTP-01 / TLS-ALPN-01 签一张
你的证书**（DV 证书只证明「这个 IP 现在归你」），然后终止 TLS 做中间人，浏览器一点警告都不给。
这条不堵，上面那张表就是空话。堵法是 DNS 上一条 **CAA 记录**（RFC 8657）：

```
h.example.com.  CAA 0 issue "letsencrypt.org; accounturi=https://acme-v02.api.letsencrypt.org/acme/acct/<主机的账户号>; validationmethods=dns-01"
h.example.com.  CAA 0 issuewild ";"
```

- `validationmethods=dns-01`：只认改 DNS 的验证 —— 中继占着 IP 也没用，它没有 DNS token；
- `accounturi`：只认**主机那个 ACME 账户**签发 —— 就算哪天 DNS token 漏了，换个账户也签不出来；
- `issuewild ";"`：不许签通配符（每台主机各签各的，见 §3）；
- CAA 按域名树往上找，挂在 `h.example.com` 上就管住了下面每一台主机。
- **只能挂在上一级，别挂在主机名自己身上**（写 `join` 那段提示时才想到的，完全静默）：主机名靠的是
  `*.h.example.com` 那条通配 A 记录，而 DNS 的通配只替**不存在的名字**生效 —— `mac.h.example.com`
  上一旦有任何一条记录（包括 CAA），这个名字就「存在」了，通配不再给它 A 记录，机器当场连不上。
  真要按名字单独钉 CAA（§3.5 借子域那条路），就得同时给它一条显式的 A 记录。

几条要说清楚的：

- **只有 Let's Encrypt 这一家的 `accounturi` 我们确认支持**。其他 CA 不认这两个参数时，
  `issue` 里没列的 CA 本来就签不了，所以只列 LE 一家是对的。
- 主机启动时**自己查一遍 CAA**（`dig CAA`），不对就在横幅和日志里醒目地说一句。这是一条
  **完全静默**的配置：不配它一切照常工作，只是中继多了一个后门，而且没有任何症状。
  所以它不是「建议配」，是**横幅上一直挂着警告直到配好**。
- 另一道是**事后发现**：主机定期查一次证书透明日志（crt.sh），看这个名字下有没有不是自己签的证书。
  CAA 是防，CT 是查，放第二期。

## 2. 架构

```
           手机浏览器 / App                         云（你的 VPS）                       你的 Mac
 ┌──────────────────────────────┐        ┌──────────────────────────┐        ┌──────────────────────────┐
 │ https://mac.h.example.com    │──TLS──▶│ :443  读 SNI → 查表       │        │ herdr-web                │
 │ （TLS 握手对面是 Mac）         │        │   mac → 那条隧道           │═隧道══▶│  中继监听（新的第五个口）   │
 └──────────────────────────────┘        │   原样转字节，不解密        │ yamux │  TLS 在这里终止            │
                                         │                          │◀══════│  主动连出去 + 断线重连      │
                                         │ :443  relay.example.com  │  出站  │                          │
                                         │   （中继自己的控制面）      │        │                          │
                                         └──────────────────────────┘        └──────────────────────────┘
```

### 2.1 中继（`cmd/herdr-relay`，新）

一个独立的小二进制，跑在 VPS 上，**不含 herdr-web 的任何业务**：

- `:443` 一个监听，读 ClientHello 的 SNI：
  - SNI 是 `relay.example.com` → 自己终止 TLS（这张证书中继自己签，HTTP-01 就行），这是**主机
    连进来的控制面**；
  - SNI 是 `<名字>.h.example.com` → 查表找到那台主机的隧道，开一条子流，**连同已经读出来的
    ClientHello 一起**原样转过去，之后双向拷字节；
  - 别的一律断开（不回任何东西，不给扫描器一个指纹）。
- 每条子流的开头先写一个**小头**（两字节长度 + `{"src":"ip:port"}`），带上手机的真实 IP。
  不用 PROXY protocol：这是自己两头之间的私有协议，没有第三方要读它，引一个格式只多一处解析。这一条要紧：走 frp 时
  所有请求在主机眼里都是 `127.0.0.1`，限速整层空转（SECURITY.md §8「frp 把两个默认策略打穿了」
  最阴的那条）；中继这条路**白捡回真实 IP**。中继被拿下时它能伪造这个头 —— 后果只是限速按
  错的 IP 算，不涉及认证。
- 落盘只有一张表：`{名字, 主机公钥, 注册时间}`，外加**邀请码的哈希**。没有一个能登录任何东西的秘密。

### 2.2 主机怎么连上去

```bash
# VPS 上（一次）：出一个邀请码，30 分钟、一次性，绑死这一个主机名
herdr-relay invite mac.h.example.com

# Mac 上（一次）：拿邀请码注册这个名字，生成一对 Ed25519，私钥留在 ~/.herdr-web/relay/
herdr-web relay join https://relay.example.com mac.h.example.com <邀请码>
```

之后服务本身就会连（配置照规矩**只走环境变量**：`HERDR_WEB_RELAY_URL` + 名字，`join` 只是
把这两行和密钥准备好，并顺手打印要加的 CAA / DNS 记录）。为什么要邀请码：这台中继是你自己的，
不能让路过的人在上面注册名字 —— 不然别人能占掉 `mac` 这个名字，或者拿你的 VPS 当免费隧道。

- 连接：主机 → `wss://relay.example.com/tunnel`，**用 WebSocket 包一层**再在上面跑 yamux 多路复用。
  多这层 WebSocket 是为了穿得过公司网络里那种只放行 HTTP(S) 的出口代理；
- 认证：中继发一个随机挑战，主机用私钥签（Ed25519），中继拿表里的公钥验。没有共享秘密，
  所以中继那张表泄露了等于没泄露；
- 掉线：退避重连（0.5 → 30 秒），和终端那层自动重连同一个思路；
- 同一个名字只认一条隧道，新的顶掉旧的（Mac 睡醒之后旧连接常常是僵的，等它超时要几分钟）。

### 2.3 主机上：第五个口

主机把从隧道里冒出来的子流当成一个 `net.Listener`（`relay.Listener`），喂给同一个 HTTP 服务。
它在规则上**完全等同于原来的公网口**（`auth.FromPublicPort` 为真；公网口本身 2026-10-23 下线了，名字留着）：

- 本机免配对、旧 token 的 loopback 档一律不认；限速的本机豁免关掉；TLS 强制；
- 判据照旧是「**落在哪个监听上**」—— 子流从隧道来，就是公网，不看源地址、不看 Host。
  （DEPLOY.md 那张表现在是「四个口」：公网口下线之后，中继隧道就是唯一的公网入口。）
- **不复用主口**：主口那道「只服务本地网络」的检查看的是对端地址，而隧道子流在进程里压根
  没有一个真的对端地址（子流头里那个是中继说的）。接到主口上，要么被 403，要么为了让它
  过去得在主口上开个口子 —— 后者就是 SECURITY.md §8 那个「别退回成一个布尔开关」。

`HERDR_WEB_PUBLIC_URL` 和 `HOSTNAME` 由 `HERDR_WEB_RELAY_URL` + 名字推出来（显式配了照样以
配的为准），所以启动横幅上的二维码直接就是 `https://mac.h.example.com/?pair=…`。

## 2.3b 隧道上的 WebSocket：yamux 的超时错误要换成标准库那个

真机上撞上的、**单测原来测不出来**的一条（原来的端到端只发普通 HTTP）：走中继时终端连上就断
（服务端「前端断开」、页面「会话结束了」），同一条路上的普通请求全都正常，局域网那条路也正常。

链条是：net/http 在 Hijack（WebSocket 升级）时用一个**早就过期**的读期限打断后台那次读，打断完
再清掉 —— 期限超时在这里是正常流程；yamux 的 `ErrTimeout` 报 `Temporary()==false`；crypto/tls
见到非临时的读错误会**永久记住**，这条 TLS 连接之后每次读都失败。普通 TCP 的
`os.ErrDeadlineExceeded` 报 `Temporary()==true`，所以只有隧道这条路坏。治法在 `relay.srcConn`：
读写的超时错误统一换成 `os.ErrDeadlineExceeded`。`TestWebSocketThroughTunnel` 盯着。

## 2.4 前面已经有反代占着 443（实际部署就是这样）

VPS 上 443 常常已经被 Traefik / nginx 占着、挂着别的站点。那时中继不独占 443：

- **主机名那条路让反代做 TLS 透传**（Traefik 的 TCP 路由 + `tls.passthrough`，nginx 的 `stream` +
  `ssl_preread`），转到中继的 `HERDR_RELAY_LISTEN`；
- **控制面让反代正常终止 TLS**，转到中继的明文 `HERDR_RELAY_CONTROL_LISTEN`。反代和中继在同一台
  VPS 上，信任边界没变；控制面上只有签名和元数据；
- 中继只看得到反代的地址，所以反代要加 **PROXY 头**、中继开 `HERDR_RELAY_PROXY_PROTOCOL=1`
  （REQUIRE：没带头的连接一律拒，不然谁直连这个口都能自己写一个头冒充来源）。

两条实际部署时撞上的，都**完全静默**：

- **Traefik 里同一个域名有 http 路由（带 TLS）时，TCP 透传路由抢不过它**，给 TCP 路由加
  `priority=1000` 也不行。表现是证书还是 Traefik 自己那张、请求进的还是老后端，一个错都不报。
  只能把那条 http 路由删掉。从「Traefik 解密」迁到「透传」时，旧路由一定是在的。
- 验证的判据是**握手拿到的证书是不是主机上那张**（看签发者 / 到期日 / 指纹），不是「页面打得开」——
  旧路由还在时页面也打得开。

## 3. 证书：谁签、存在哪儿

- **签发方是 Let's Encrypt。** 发起申请的 ACME 客户端（现成的 `internal/acme`）跑在**每台主机
  自己身上**，ACME 账户密钥、证书、证书私钥都存在那台主机的 `~/.herdr-web/data/acme/`，到期前
  30 天自己续、热重载。**证书和私钥从不离开主机**，中继一次都碰不到。
- **一台主机一张证书，只签自己那个名字**。不签 `*.h.example.com` 通配 —— 那张私钥得在每台主机
  上各放一份，一台被拿下所有主机一起能被冒充。
- 验证方式只用 DNS-01（CAA 里写死，§1.1）。DNS-01 要改一条 TXT 记录，「这条 TXT 谁来写」
  分两种情况，见下一节。

## 3.5 多台机器、多个人

路由表本来就是「名字 → 主机公钥」，所以多台机器 / 多个人在中继这一侧没有任何特殊之处：
**每台主机一条隧道、一把自己的密钥、一个自己的名字**。难的是名字和证书怎么分。

### 名字按人分一层

```
mac.bysir.h.example.com     ← 你的 Mac
pc.bysir.h.example.com      ← 你的第二台
herdr.alice.com             ← 第二个人，用她自己的域名（推荐）
mbp.alice.h.example.com     ← 第二个人，没有域名，借你的
```

多这一层（`bysir.` / `alice.`）不是为了好看，是因为 **passkey 的 RP ID**：

- 你的两台机器想共用一把 passkey，就把 RP ID 设成 `bysir.h.example.com`（父域）。
- **绝不能把 RP ID 设成 `h.example.com`。** RP ID 下面所有 origin 都能请求这把 passkey 的签名，
  而 alice 的主机也在 `h.example.com` 下面、页面由她的主机发：她的页面可以去**你的**主机那儿
  拿一个登录挑战，让你的浏览器用你的 passkey 签了，再转交给你的主机 —— 等于用你自己的 passkey
  登你的机器。WebAuthn 的防钓鱼只防「不同 RP ID」，同一个 RP ID 下的站点之间是互相信任的。
  所以 RP ID 只能落到**一个人自己的那一层**。

每台机器的设备表、配对各是各的（和 SECURITY.md §8「两套凭据完全独立」一样）：新手机进第二台
机器还是要配一次对，或者用共享的 passkey 登录一下。

### TXT 谁来写：两种

**A. 有自己的域名（第二个人推荐这条）**：和你自己现在的 D 档完全一样 —— 她的 DNS token 放在
她自己的机器上，自己写 TXT、自己签，CAA 也配在她自己的域名上。她只需要加一条
`herdr.alice.com CNAME relay.example.com`。**这条路上她连你都不用信**：你作为中继的主人，能做的
和「VPS 被拿下」那张表一样多，也就是看元数据、断网。

中继这边要多做一件事：**注册一个外部域名时要验所有权**。她 `join` 时，中继要求
`_herdr-relay.herdr.alice.com` 上有一条 TXT，内容是她主机公钥的指纹。不验的话，谁都能把
`herdr.alice.com`（或者你的名字）注册到自己的隧道上 —— 证书过不去所以偷不到内容，但能把她的
流量劫走，让她一直连不上。

**B. 没有域名，借你的子域**：她的机器拿不到你 DNS 的 token（Cloudflare 的 token 不能只给一个
名字的权限，给了就是整个域名的改动权）。所以用 **acme-dns 那种委托**：

```
# 你的 DNS 里（Cloudflare），给她开户时加两条，以后不再动：
_acme-challenge.mbp.alice.h.example.com  CNAME  <随机 id>.acme.example.com
mbp.alice.h.example.com  CAA 0 issue "letsencrypt.org; accounturi=<她的 ACME 账户>; validationmethods=dns-01"
```

- `acme.example.com` 这个子区 NS 指向中继，中继上跑一个极小的权威 DNS，**只答 TXT**，只有持有
  对应主机私钥的隧道能写自己那个 id。于是她的机器能完成 DNS-01，你的 Cloudflare token 不用离开你。
- **中继被拿下也签不出她的证书**：它能答 TXT，但 CAA 里钉的是**她的** ACME 账户，账户私钥在她
  机器上；而 CAA 记录在 Cloudflare 上，中继改不了。
- **但你能签。** 域名在你手里，你改一下 CAA 就能给她的名字签证书、做中间人。这是物理事实，任何
  机制都绕不过去：**谁管 DNS，谁就能签证书**。所以 B 这条路上她信的不是 VPS，而是**你这个人**。
  熟人之间可以接受；要连你都不信，就走 A。这句话要写进她看到的使用说明里，不能藏起来。
- CT 日志照样能事后发现：她的主机定期查自己名字下的证书，出现不是自己签的就告警。

你自己的机器也可以走 B（不往 Mac 上放 Cloudflare token，A6 少一个能读走的东西），这时「能签你
证书的」也只剩你自己。

### 开户 / 销户

- 开户是你在**自己机器上**跑的命令（`herdr-relay admin add alice --hosts 3`）：出邀请码，B 那种
  还顺手用**你本机**的 DNS token 把那两条记录加上。Cloudflare token 不放到 VPS 上。
- 每人一个配额（几台主机、并发连接数、流量上限），中继按人计。中继给别人用，就等于你的 VPS
  带宽在替别人走流量。
- 销户：删路由表那一行，B 那种再删两条 DNS 记录。她主机上的东西（证书、设备表）不用管，
  那本来就是她的。
- 中继上仍然**没有用户密码、没有登录**：「谁」就是「哪把主机公钥」。

## 4. 局域网直连：App 里换路，不换 origin

现在网页那条直连（`useLanDirect`）有一串绕路，都是浏览器逼的：直连口必须 https → 只能自签 →
每台设备在那个 IP 上点一次「继续访问」→ IP 一变那一下作废 → 换 origin 就得带一份新凭据过去
（交接令牌）→ IP 上用不了 passkey → 重验窗口一过只能重配对。根子只有一个：**浏览器不让网页
决定「这个域名连到哪个 IP」**，于是只能换 origin。

### 4.1 「不安全的 HTTP」解决的不是这个问题

App 确实能放行明文（debug 包现在就开着）。但明文直连等于把 SECURITY.md 里 A2 那一行原样
放回来：同一个 Wi-Fi 上抓包就是**设备 cookie + 整个终端画面 + 每一次按键**，而「同一个 Wi-Fi」
恰恰是直连生效的那个场景（咖啡店、公司、酒店）。cookie 被抓走之后在公网那条路上照样能用。

**App 真正多给我们的不是「能不安全」，而是「能决定连到哪儿」。** 所以直连不需要降级：

### 4.2 做法：WebView 走 App 自己的本地代理

androidx.webkit（我们现在用 1.14）有 `ProxyController.setProxyOverride`：给这个 App 里所有
WebView 指一个 HTTP 代理，配上 `setReverseBypassEnabled(true)` 就**只代理指定的那几个主机**。

```
WebView ──CONNECT mac.h.example.com:443──▶ App 内的代理（127.0.0.1:随机口）
                                              ├─ 在家：直接拨 192.168.1.5:<直连口>
                                              └─ 不在：直接拨 mac.h.example.com:443（走中继）
            ◀──────────── TLS 从 WebView 一路到 Mac，代理只看到密文 ─────────────▶
```

这样换来的东西：

- **origin 不变**，永远是 `https://mac.h.example.com`。cookie、localStorage（排布镜像、prefs
  镜像）、passkey、Service Worker 全是同一份。交接令牌、第二份设备凭据、「继续访问」、
  「地址变了」那一整套在 App 里**全部用不着**。
- **证书是 WebView 自己验的，验的是真证书**：主机在直连口上按 SNI 给出同一张 `mac.h.example.com`
  的证书。代理连错了地方（地址变了、局域网里另一台机器占了那个 IP）的后果是 **TLS 失败 →
  代理退回中继那条路**，绝不会「连错还不知道」—— 这是比「App 自己钉指纹」更好的性质：
  验证不在我们自己写的代码里。
- WebSocket 也走 CONNECT，终端、chat 的长连都跟着换路。
- 代理本身不碰明文，不加任何凭据（cookie 在 WebView 自己的罐子里）—— 手机上别的 App 连这个
  本地口，能做的事和直接连公网上那个域名一样，没有多拿到任何东西。

选路：

- 候选地址从主机来（现成的 `/api/lan`，页面通过桥告诉壳；**每次现报**，规矩和现在一样）；
- 什么时候重新探：App 回前台、网络变了（`ConnectivityManager` 回调）；探法是对候选地址做一次
  带 SNI 的 TLS 握手、验证书，900ms 超时（和网页那边同一个数）；
- **已经建好的连接不搬**：新的 CONNECT 走新路，旧的自然断掉时由现成的自动重连接上。离开
  Wi-Fi 那一下直连的那几条会断，终端会自己连回来 —— 这本来就是今天锁屏回来的体感。

### 4.3 主机那边要动的

- 直连口（`HERDR_WEB_LAN_PORT`）**按 SNI 选证书**：SNI 是中继那个名字就给真证书，否则照旧给
  本地 CA 签的自签证书（给人手打 IP 打开的那种）。
- 那个口照旧只服务本地网络（`lan.PeerIsLocal`）。但 App 走它时**不需要交接令牌** ——
  cookie 本来就是这个 origin 的。
- 网页那边：`useLanDirect` 只做一件事 —— 在 App 里把候选地址递给壳。

### 4.4 浏览器那条路

**没有了**（2026-10-25 下掉）。原来是「嗅探 → 问 → 交接令牌 → 换 origin」，除了上面那串麻烦，
还有一条更糟的：人在 IP 上点过「继续访问」之后，嗅探请求带着证书错误成功，Chromium 把**公网那一页**
记成「加载过证书有错的内容」，passkey 从此在那页上按不动（用户报的）。浏览器在家也走中继。
想让浏览器也直连，唯一不换 origin 的办法是在家里路由器上做**内网 DNS 覆盖**
（`mac.h.example.com → 192.168.1.5`，并让主机在 443 上也听一份）—— 当可选项，不做进代码。

## 5. 威胁对照（新增的部分）

| 谁 | 能干什么 | 挡在哪儿 |
|---|---|---|
| 中继 VPS 被拿下 | 看元数据、断网 | 内容：TLS 在主机终止；页面：主机发 |
| 中继 VPS 被拿下 + 去签证书做中间人 | **想**签一张 `mac.h.example.com` | CAA（`dns-01` + `accounturi`）；主机启动时查 CAA；CT 事后查 |
| 中继那张表泄露 | 拿到每台主机的公钥 | 公钥本来就公开；冒充主机要私钥 |
| 有人在中继上抢注名字 / 白嫖隧道 | — | 邀请码（一次性、30 分钟、绑死主机名、只存哈希） |
| 冒充一台主机连上中继，把流量引走 | 抢到流量也握不了手 | 隧道认证要主机私钥；就算抢到，手机这边 TLS 不过 |
| 有人把别人的外部域名注册到自己隧道上 | 劫走路由（偷不到内容） | 注册外部域名要验 `_herdr-relay` TXT |
| 同一个中继上的另一个用户 | 借同一个 RP ID 转交 passkey 签名 | RP ID 只落到每个人自己那一层（§3.5） |
| 中继的主人（借子域的用户眼里） | 改 CAA 签证书 | **挡不住**，谁管 DNS 谁能签；要么信他，要么用自己的域名 |
| 中继伪造子流头里的 IP | 限速按错的 IP 算 | 只影响限速，不影响认证 |
| 同一个 Wi-Fi 上抓 App 的直连流量 | 只见 TLS | 直连也是同一张真证书，**不开明文** |
| 手机上别的 App 连 App 的本地代理口 | 和直接连公网域名一样 | 代理只转 TLS 密文，不注入凭据 |
| Mac 上被注入的 agent 读 `~/.herdr-web/relay/` 的私钥 | 能冒充这台主机连中继 | 它早就有你的 shell 了（A6 的老结论）；证书私钥 / DNS token 同理 |

## 6. 不做什么

- **中继终止 TLS / 中继托管页面** —— §1.1。
- **把设备表 / passkey 搬到云上做「统一账号」** —— 云上不该有任何一份能用来登录的东西。
  多台主机共用 passkey 走 RP ID 设成父域，不走账号系统。
- **直连走明文** —— §4.1。
- **在中继上看一眼内容做个「在线状态」之类的** —— 要什么状态，主机通过隧道的控制面自己报
  （上线 / 下线），内容那条路中继一个字节都不解析。
- **一份通配证书发给所有主机** —— §3。

## 7. 分期

1. ✅ **中继 + 主机隧道**：`cmd/herdr-relay`（SNI 路由、控制面、邀请码、子流头）、
   `internal/relay`（主机侧：join、隧道 `relay.Tunnel` 当公网口）、按名字推 `PUBLIC_URL`。
   *单测已验*（`internal/relay/relay_test.go`）：两台主机各走各的；TLS 在主机终止（换一张中继
   没有的证书照样握得上）；主机看到的对端是手机地址；邀请码一次性、绑死名字（原来还有一道「名字必须在 `HERDR_RELAY_ZONE` 下面」，2026-10-25 删了：名字已经被邀请码绑死，它什么都没多挡，只让一台中继接几个域名时要改配置）；
   换钥匙冒充被拒；新隧道顶掉旧的。没 join 就起服务 → 拒绝启动；`TLS=off` 配中继 → 拒绝启动（`TLS=proxy` 2026-10-23 起无论配不配中继都拒绝启动）。
   *还要在真 VPS 上验*：浏览器从 `https://mac.h.example.com` 配对 / passkey / 终端 / chat 全通；
   VPS 上 `tcpdump` 里看不到明文；中继控制面的 TLS-ALPN-01 自签发真能签下来。
2. **多人 + 加固**：`herdr-relay admin`（开户 / 配额 / 销户）、外部域名所有权验证、中继上的
   acme-dns（借子域那条路）；主机启动时查 CAA、横幅警告；CT 定期查；中继侧按人 / 源 IP 限速。
   第 1 期只做「你自己的多台机器 + 每台自带 DNS token」，已经够你自己用两台。
3. ✅ **App 换路**（2026-10-23 真机验过：小米，WebView 支持反向绕过；在家连接走 `192.168.x.x:7790`，一次请求 11ms）。踩过一条**静默**的：本机代理要**显式绑 127.0.0.1** —— Android 的 `InetAddress.getLoopbackAddress()` 是 `::1`，WebView 按规则连 127.0.0.1 报 `ERR_PROXY_CONNECTION_FAILED`，页面上只是「Failed to fetch」，而从 adb forward 测一切正常。还没验：离开 Wi-Fi 时多久连回中继。
   **界面上怎么看走的哪条**：不另加标签，就是顶栏左上角那个状态点 —— 连上时绿 = 直连、蓝 = 中继
   （用户点名的配色；token 是 `--color-relay`，跟着调色板的蓝走）。按**此刻开着的**隧道算（壳统计、`route`
   消息报给页面），两条都有就算中继。由此来的一条：**开页面之前先拿上次的候选探一次**（最多 1.5 秒，
   候选按域名存在壳里）—— 不然页面和终端那条 WebSocket 先经中继建好，人在家里那颗点也一直是蓝的。
   **小米这类「双网」机型** Wi-Fi 信号一差（或判它上不了外网）就把默认网络切到蜂窝、Wi-Fi 标成
   `EXITING` 但还连着。不指定网络的 socket 全走默认网络，于是人在家、Wi-Fi 连着，局域网却「探不通」
   （用户报的「等了 30 秒没切」；日志里是从 10.x 的蜂窝地址去连 192.168.x、ENETUNREACH）。所以
   局域网那几条连接（探测 + 往直连口拨）**绑在 Wi-Fi 的 Network 上**（`LanRoute.bindLan`），并且
   `requestNetwork` 申请着 Wi-Fi（不要求能上外网）—— 没人要的 EXITING 网络会被系统拆掉。要两个普通
   权限：`ACCESS_NETWORK_STATE`、`CHANGE_NETWORK_STATE`，漏了都是**静默**的（回调注册失败，只有一行 W 日志）。
   **切过去那一刻：壳把走中继的连接全部掐掉**（`LocalProxy.closeRelay`）。只让新连接走新路不够 ——
   终端那条长连接、浏览器池子里空闲的 keep-alive 都还挂在中继上，点一直是蓝的。浏览器被掐断的会自己
   重建，终端的自动重连（Session.retry）自己就走局域网了。**第一版不是这么做的**：页面在「切过去的那一下」
   重连终端，撞上过时机问题（用户报的「在局域网怎么还是中继」）—— 壳是「先作废、再探」，中间几十毫秒的
   空档里终端恰好重连就落到了中继上，等探通时「切过去」那一下已经过了；而池子里那些空闲连接它也管不着。
   掐连接只看「此刻有没有走中继的」，没有时机问题；拨号时局域网还没探通、连上时已经探通的那种还会当场
   补掐（试过局域网没拨通才退到中继的那种是正当退路，不动）。离开 Wi-Fi 那个方向不用管：局域网那些
   连接自己会断，终端自动重连走中继。
   **什么时候探**：没有定时轮询，靠事件 —— App 启动（开页面前用上次的候选）、回前台、默认网络变化、
   Wi-Fi 连上 / 断开、页面报候选；外加兜底：走中继而 Wi-Fi 连着时每 20 秒再探一次。
   原计划：**App 换路**：`ProxyController` + 本地 CONNECT 代理 + 选路；直连口按 SNI 出真证书；网页那边
   在 App 里关掉 `useLanDirect`。**要在真机上验**：`PROXY_OVERRIDE_REVERSE_BYPASS` 这台手机的
   WebView 版本支不支持（不支持就退回「代理所有主机，非目标的原样直连」）、WebSocket 走不走
   CONNECT、离开 Wi-Fi 时终端多久连回来。
4. 以后：NATIVE-APP.md §4b 那个推送中转可以并进 `herdr-relay`（同一台 VPS、同一个控制面）。
